# 2. 核心数据流

以最典型的"Web 模式：上传 Excel → 配置条件 → 执行复制"为主线，逐段落到文件:行号。

## 阶段 0：环境初始化（每次启动）
- `start_web.py` / `start_desktop.py` 设置环境变量 → `webapi/utils/pathing.py: get_runtime_dirs()` 解析 `user_dir / output_dir / logs_dir / config_dir`。
- `webapi/app.py: create_app()` 注册 4 个 router，可选 `CORSMiddleware`（`app.py:18-33`，读 `CORS_ORIGINS` 环境变量，缺省放行 `*`）。

## 阶段 1：列画像（"自动推断标识列"）
**入口**：`POST /api/excel/columns` → `analyze_excel_columns()`（`excel.py` router）
1. `excel_service.load_excel(input_path)`（`excel_service.py:24-37`）：`pandas.read_excel(engine="openpyxl")` → `List[Dict]`。
2. `file_matcher.analyze_columns(records)`（`file_matcher.py:38-91`）：
   - 对每列算 `ColumnProfile`（`_profile_column`，`file_matcher.py:184-255`）。
   - 判定 `is_identifier_candidate`：唯一值占比高 + 非纯数值范围（`file_matcher.py:215-255`）。
   - 返回的 `recommended_identifier` 取"候选中唯一值占比最高、且基数适中"的列（`file_matcher.py:84-91`）。
3. 返回 `ExcelColumnsResponse`（含每列 `candidates/profiles/recommended_identifier`）。

> 前端 `SelectSource.jsx` 据此预填"建议标识列"，但用户可改。

## 阶段 2：条件过滤（"用户想挑哪些记录"）
**入口**：`POST /api/query/filter` → `filter_records()`（`query.py` router）
1. 解析 `FilterRequest`（条件列表 + 模式）。
2. `QueryEngine.from_records(records)`（`query_engine.py:30-60`）：建立 `column_index`（列→值集合），为 range 模式预排序（`_build_sorted_index`，`query_engine.py:62-85`）。
3. `engine.filter(conditions, mode)`（`query_engine.py:87-118`）：
   - `exact/contains/fuzzy` 走 `_eval_scalar`（逐行 `any` 命中，`query_engine.py:176-210`）。
   - `range` 走 `_eval_range`，借助预排序索引二分裁剪（`query_engine.py:212-250`）。
   - `mode=all` 用 `&`，`mode=any` 用 `|` 组合掩码（`query_engine.py:108-118`）。
4. 返回 `FilterResponse`（含 `matched_count` 与命中行索引）。

## 阶段 3：匹配摘要（"磁盘上能找到多少"）——核心桥梁
**入口**：`POST /api/query/match` 与 `POST /api/excel/match`
- `excel_match()`（`excel.py`）：`build_matcher(records, identifier_column, conditions)` 生成闭包；
  `get_identifier_tokens(record)`（`file_matcher.py:99-138`）从记录抽"文件名里应出现的标识 token"；
  `match_files(input_dir, matcher, ...)`（`file_matcher.py:140-182`）**遍历输入目录全部文件**（含子目录，`_iter_files`，`file_matcher.py:260-280`），对每个文件名依次试每个 matcher 标识，命中即归入 `matched_files` 并记 `record_id`。
- 产出 `MatchDetailResponse` / `MatchSummaryResponse`（`schemas.py`）：含前文/后文片段、冲突数、未匹配数。
- **关键亮点**：每个匹配都带 `context_before/context_after`（从文件名切出的标识两侧文本），让用户在复制前**肉眼核对"这条文件是不是真对得上这条记录"**——这是防误复制的核心可解释性设计。

## 阶段 4：执行复制（"落地"）
**入口**：`POST /api/workflow/execute` → `execute_classification()`（`workflow.py` router）
1. `WorkflowService.run(...)`（`workflow.py:30-95`）：
   - 重新 `match_files`（确保与预览一致，不信任前端传来的匹配结果——**安全设计**）。
   - 对每个 `matched_file`：`_copy_file`（含 `_dedupe_target`，同名冲突按 `keep` 策略命名 `name (1).ext`，`workflow.py:97-150`）。
   - 统计 `copied / skipped / errors`。
2. `write_report(result, path)`（`workflow.py:152-200`）：写 `classification_report.xlsx`（含 matched/unmatched/conflicts 三张表）。
3. `append_log(...)`（`system_io.py`）：写 `classification.log` 到 `logs_dir`。
4. 返回 `WorkflowResultResponse`（含 `copied_files / report_path / log_path`）。

## 阶段 5：输出落盘
- 复制文件 → `output_dir`（来自 `pathing` runtime 上下文）
- 报告 → `output_dir/classification_report.xlsx`
- 日志 → `logs_dir/classification.log`

## 调用链一句话版
```
UI:选Excel → /excel/columns(analyze_columns)
   → UI:设条件 → /query/filter(QueryEngine.filter)
   → /excel/match(build_matcher+match_files) 预览
   → UI:点执行 → /workflow/execute(WorkflowService.run→copy+report+log)
```

## 值得注意的数据流特征
- **预览与执行"双算匹配"**：执行时重新 `match_files` 而非复用预览结果，牺牲少量重复 IO 换取"所见即所得、且不被中间篡改"的安全性。
- **全内存、无持久化状态**：每次请求都是 `records` 随请求体传入；服务端不保存会话。Web 模式天然无状态、可水平扩展（尽管当前部署是单机）。
