# 3. 关键模块拆解

挑 4 个决定项目灵魂的模块，按"做什么 / 怎么做 / 为什么"拆解。

---

## 模块 A：`services/file_matcher.py` —— 列画像 + 文件匹配（项目心脏）

### 做什么
把"Excel 元数据表"与"磁盘上散落的文件名"桥接起来：自动判断哪一列适合当标识，并从每条记录抽出"文件名里应当出现的标识 token"，再扫描输入目录把文件对号入座。

### 怎么做（关键函数）
1. **`analyze_columns(records)`**（`file_matcher.py:38-91`）
   - 对每列调 `_profile_column`（`file_matcher.py:184-255`）：
     - `cardinality` = 唯一值数；`uniqueness_ratio` = 唯一值/总行数。
     - `_looks_like_range(values)`（`file_matcher.py:257-279`）：若列中数值呈连续区间（如 `1-100`），判为非标识列——因为范围不适合做精确文件名匹配。
     - `is_identifier_candidate` = `uniqueness_ratio` 高 且 非纯范围 且 缺失率低。
   - `recommended_identifier`：候选里 `uniqueness_ratio` 最高者，若都为 0 则回退到"基数最大的文本列"。

2. **`get_identifier_tokens(record)`**（`file_matcher.py:99-138`）
   - 从记录的标识列值抽若干"子串 token"（按分隔符/空白切分），用于后续文件名子串匹配。返回 `List[str]`。
   - **为什么这样设计**：文件名往往是"前缀_标识_后缀"或"标识-描述"形态，单取整列值做 `==` 会大量漏配；抽 token 后用 `in` 子串匹配更鲁棒。这是"模糊但安全"的折中。

3. **`match_files(input_dir, matcher, recursive, ...)`**（`file_matcher.py:140-182`）
   - `_iter_files`（`file_matcher.py:260-280`）递归遍历（除非 `recursive=False`）。
   - 对每文件：`matcher(relative_path, filename)` 闭包逐个试 token；命中记 `matched_files` 并附 `record_id + context_before/after`。
   - `conflicts`：同一文件被多条记录匹配；`unmatched_files`：遍历完无任何记录匹配的文件；`unmatched_records`：没有任何文件匹配的记录。

### 为什么这么做（设计意图）
- **"标识列自动推断"是为了降低用户认知负担**：普通办公用户不懂"主键"概念，但能从"几乎每行都不同的一列"推断出来。
- **token 子串匹配 + context 回显**：核心是"宁可多匹配、也要让人看见并确认"，把误复制风险转嫁给人审，而非靠算法赌对。

## 模块 B：`services/query_engine.py` —— 条件过滤 DSL 求值器

### 做什么
把用户在前端配置的"筛选条件"（多列、多算子）编译成可复用的过滤器，对记录集求值，返回命中掩码 + 命中记录。

### 怎么做
- **`QueryEngine.from_records(records)`**（`query_engine.py:30-60`）：建 `column_index`（列名→该列所有值集合），并对数值列建 `sorted_index`（升序列表）供 range 二分。
- **`filter(conditions, mode)`**（`query_engine.py:87-118`）：
  - 逐条件生成布尔掩码 `_eval_scalar` / `_eval_range`。
  - `mode="all"` → 掩码按位与；`mode="any"` → 按位或。
- **算子实现**：
  - `exact`：`str(a).strip()==str(b).strip()`（可选 `case_insensitive`）。
  - `contains`：子串 `in`。
  - `fuzzy`：`difflib.SequenceMatcher.ratio >= threshold`（`query_engine.py:212-223`）——轻量、无依赖的模糊匹配。
  - `range`：借助预排序索引二分定位下/上界（`_eval_range`，`query_engine.py:212-250`），复杂度 O(log n) 而非逐行扫。

### 为什么这么做
- **预建索引 + 掩码组合**：把"N 个条件 × M 行"的朴素 O(N·M) 降到"建索引 O(M log M) + 求值 O(N·M')"，range 条件下更接近 O(N log M)。对 Excel 常见几千行的体量足够。
- **fuzzy 选 `difflib` 而非外部库**：再次印证"零外部依赖"总原则，牺牲一点匹配质量换部署简单。

## 模块 C：`services/workflow.py` —— 编排器（匹配→复制→报告→日志）

### 做什么
把前面所有零件串成一条"可执行"的流水线，并负责副作用（磁盘复制、写 Excel 报告、写日志）。

### 怎么做
- **`WorkflowService.run(...)`**（`workflow.py:30-95`）：
  1. **重新执行 `match_files`**（不信任前端预览结果），保证执行态与用户看到的一致、且防篡改。
  2. `_copy_file`（`workflow.py:97-150`）：
     - `_dedupe_target`：目标已存在时按 `keep` 策略（`first/last`，默认 `first`）选择覆盖或重命名 `name (1).ext`。
     - 统计 `copied / skipped / errors`，错误进 `errors[]` 不中断整体。
  3. `write_report(result, path)`（`workflow.py:152-200`）：用 `openpyxl` 写三张表（matched/unmatched/conflicts）。
  4. `append_log`（`system_io.py`）：追加写 `classification.log`。

### 为什么这么做
- **"重算匹配"是关键安全决策**：前端是可信度未知的环境（浏览器），若直接信任前端传来的"已匹配文件清单"，等于让客户端决定服务器复制什么文件——这是 SSRF/路径穿越类风险源头。重算把"决定权"收回服务端。
- **错误不中断（partial success）**：归档任务常是"几百个文件里坏一两个"，整体失败重试成本高于局部跳过。

## 模块 D：`webapi/utils/pathing.py` + `system_io.py` —— 双模部署的运行时抽象

### 做什么
把"这个程序此刻是桌面 exe 还是 Web 服务"的差异，收敛成一组目录路径，业务代码无需关心部署形态。

### 怎么做
- **`get_runtime_dirs()`**（`pathing.py`）：
  - 若 `FILECLASSIFIER_DESKTOP_MODE` 置位 → 用 `runtime_dir` 环境变量（pyinstaller 的 `_MEIPASS`/用户目录）作为 `user_dir`，其下派生 `output/logs/config`。
  - 否则（Web 模式）→ 用仓库相对目录 + `APP_*` 环境变量覆盖。
- **`system_io.py`**：`write_text/read_text/append_log/ensure_dir`，统一 `UTF-8` + `errors="replace"`，并集中处理 `FileNotFoundError` 等 IO 异常，避免散落 try/except。

### 为什么这么做
- **部署形态差异是真实成本**：桌面要"单 exe、数据跟 exe 走"；Web 要"数据在服务器某固定目录"。集中到一个函数，使 `workflow`/`excel_service` 完全不感知差异——这是该项目最具"工程化成熟度"的一笔。

## 模块 E（附带）：`services/mock_data.py` —— 自解释的测试夹具
- `generate_mock_excel(path, base_name, n)` 生成含标识符列的 Excel。
- 刻意构造 4 类情景（`file_matcher.py` 测试依赖它）：`archive/`（子目录文件）、`conflicts/`（1 文件匹配 2 记录）、`unindexed/`（Excel 无对应列的文件）、`Complaince`/`Compliance`（故意拼错，验证 fuzzy）。
- **为什么值得提**：把"测试想覆盖的边界情形"直接编码进夹具命名， reviewer 一眼看懂测试意图，是可复用的最佳实践。
