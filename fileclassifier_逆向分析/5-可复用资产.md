# 5. 可复用资产

下列思路/模式/代码可迁移到其它项目（尤其是"单机工具工程化""带 UI 的数据处理 Pipeline"类需求）。

## 5.1 模式：薄接口 + 厚业务 + dataclass 实体
- **做法**：FastAPI 路由只做「收参 → 调 service → 包 schema」，所有逻辑在 `services/` 且只用标准库 + pandas。业务实体用 `dataclass`，仅 HTTP 边界用 `Pydantic`。
- **可迁移场景**：任何"后端服务 + 重业务逻辑"的项目。收益：业务逻辑可脱离框架单测，重构 API 层不影响核心。
- **源码锚点**：`webapi/*_router` 均 < 40 行；`services/*` 不 import fastapi。

## 5.2 模式：双模部署的运行时目录抽象
- **做法**：`pathing.get_runtime_dirs()` 用环境变量（`FILECLASSIFIER_DESKTOP_MODE` / `runtime_dir`）决定数据/输出/日志落点，业务层零感知。
- **可迁移场景**：同一套代码既打桌面 exe（pyinstaller）又跑 Web 服务。
- **源码锚点**：`webapi/utils/pathing.py`。

## 5.3 模式：预览—确认—执行 + 服务端重算
- **做法**：变更类操作先在"预览"接口返回可核对的中间结果（带 context 回显），"执行"接口**服务端重新计算**而非信任前端传来的结果。
- **可迁移场景**：任何"前端触发服务器副作用（复制/移动/删除文件、批量写库）"的场景。是防越权/防篡改的低成本手段。
- **源码锚点**：`workflow.py:30-95` 重算 `match_files`；`file_matcher.py` 的 `context_before/after`。

## 5.4 组件：列画像自动推断"标识列"
- **做法**：对每列算 `uniqueness_ratio` / `cardinality` / 是否纯范围，自动推荐"最适合当主键"的列。
- **可迁移场景**：Excel/CSV 导入向导、数据清洗工具、任何需要"猜用户想用哪列做键"的 UI。
- **源码锚点**：`file_matcher._profile_column`（`file_matcher.py:184-255`）、`analyze_columns`（`file_matcher.py:38-91`）。

## 5.5 组件：零依赖条件 DSL 求值器
- **做法**：`MatchCondition` 描述 `{column,type,value}`；`QueryEngine` 建列索引 + 数值列预排序，exact/contains/fuzzy(range 走二分) 组合成掩码。
- **可迁移场景**：轻量筛选器、规则引擎原型，不想引入 SQLAlchemy/Elasticsearch 时。
- **源码锚点**：`query_engine.py` 全文件。

## 5.6 实践：测试夹具即文档
- **做法**：`mock_data.py` 把边界情形（冲突/未索引/拼错）直接编码进夹具目录名。
- **可迁移场景**：所有需要"让 reviewer 秒懂测试意图"的测试代码。

## 5.7 谨慎借鉴（不要直接抄）
- 多入口端口硬编码、前端 `/api` 双前缀、可能的 `storage` 死引用——这些是"坑"，应作为反面教材（统一入口、明确反代契约）。
